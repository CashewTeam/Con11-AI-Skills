USD 全称为 Universal Scene Description，即通用场景描述，是用来描述当前工作环境中 3D 场景内容的文件。

* 从场景描述角度讲，常用格式为 .usda：
   * .usda 格式有图层特性，在多人合作编辑时，可以无损地叠加编辑。
   * 不同的开发商能自己添加特有的属性，方便自身开发。以 PICO Spatial 为例，扩展后引擎可以直接使用您在 DCC 软件里标记的特殊属性。例如从编辑器输出带有 PICO Spatial 特有 SDK 组件的对象，它们以图层形式附在资源上。修改资源时，不会影响附加的组件，属于非破坏性修改，就算是在编辑器里二次编辑的材质，只要节点结构不变就没问题。
   * 在 Spatial Editor 中，通常使用 .usda 作为场景保存方式，置于 Scenes 目录下，并且会被自动打包识别，打包其引用的所有内容。
* 从资产角度出发，常用格式有 USDC 和 USDZ：
   * USDC 是二进制描述文件，它的灵活度最高，读取性能也最好。文件会自带一个同级别的 texture 文件夹，用来存纹理，这是必须的，而且是相对目录结构。一般给 Spatial Editor 提供资产时用这种格式，可能会进行二次材质编辑，有些情况下可以选择不输出材质。
   * USDZ 整合了 USDC 和 texture 文件，方便分发和直接使用，和 PICO Spatial SDK 搭配时，通常用于 AssetsLoad 直接使用，或者组合多个资产。不适合对资产本身进行二次编辑。
* 从文件保存的内容出发，它包含以下基本信息：
   * 场景里多边形的点信息、每个顶点相对于整体的矩阵变换信息、对象的变换信息、对象的骨骼信息和权重信息等。
   * 通用的 UsdPreviewSurface 材质信息是一种 PBR 材质信息的通用格式。您可以简单理解为固有色、金属度、粗糙度、透明度、自发光等基础通道的数值，以及使用的贴图，还有通道使用贴图的基础采样方式，比如使用了哪些 RGB 分量通道。同时，它也包含该材质使用的 UV 通道序号，以及 UV 的基本运算（如偏移、重复、旋转）。如果您从 DCC 软件输出标准的 PBR 材质对象，并且选择归档类型的 USDZ 格式，就能在 PICO SDK（asset）里快速使用。

## 通用性建议
USD 格式对资产中对象的节点命名很敏感。您在 DCC 软件制作阶段的命名，是引擎找节点的唯一标识。制作时要避免相同的节点命名，包括物体命名、物体 mesh 数据块命名等。USD 和其他格式不同，通常输出的结构就是项目使用的结构。

* 以 Blender 为例，基本物体的推荐命名如下：
   * **物体名称** 是物体在当前场景里的名字，无特别要求，简洁易懂即可。
   * **模型数据块名称** 是物体对应 USD 文件格式模型数据组件的节点名称，在场景里尽量保持唯一。SDK 要获取模型顶点、模型材质信息时，需检索到这个节点。材质名称无特别要求。

* USD 格式对 PBR 材质设置有要求，要使用 UsdPreviewSurface 支持转换的节点，贴图格式推荐 png。纹理名称尽量简洁明了，不能使用中文。

输出 usd* 资产时，文件名称本身也会变为一个节点，在引擎内或作为一个实体存在，因此建议对名称进行规划，提高可读性，避免过长或者难以读懂（特别是涉及开发过程中需要操作的对象）。以 Blender 为例，输出的结果通常为：

* 输出文件件名
   * 节点名
      * **多边形数据节点**，在引擎里是一个实体。

   * Editor 读入后的结果。只有输出文件名在编辑器的资产管理里有实际排序意义，在引擎使用中，以 ECS 方式，提供渲染效果信息的是节点多边形数据节点对象。如果 SDK 要动态修改材质，需查询到这一层，获取材质信息。因为 USD 输出时，会把材质信息和模型顶点信息存到多边形数据节点上。

## **编辑器资源命名**

* 美术资源名称。命名示例：Earth.usdz
* 美术资源位于 **Assets** 文件夹下
   * 模型文件
   * 贴图文件

* 工程位于 **Scenes** 文件夹下，工程是 `.usda` 文件
