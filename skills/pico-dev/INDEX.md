# PICO 开发者文档：spatial

本文帮助大语言模型理解、检索和使用 spatial 平台的 PICO 开发者文档。当前语料为中文 PICO OS 6 / Spatial SDK 6.0 导出。

## 本语料涵盖的内容

本语料覆盖 PICO OS 6 空间应用架构、Android/Kotlin 项目配置、WindowContainer 与 Stage、Spatial UI、ECS、资源、交互、追踪、渲染、动画、物理、空间音视频、混合现实环境理解、SpatialML、设计规范、教程，以及 Plugin、Emulator、Spatial Editor 工具链。最适合用于选择开发路径和定位实现文档。设计规范或纯编辑器页面不能单独支撑运行时结论；设备差异、外部 Android API 和政策仍应回到对应权威来源核验。

## 给大语言模型智能体的说明

- 默认优先使用本文代表的 6.0 语料版本，除非用户明确指定其他版本。
- 先读[了解 PICO Spatial SDK 和空间应用](docs/spatial-sdk_了解-pico-spatial-sdk-和空间应用.md)，再按问题进入空间容器、UI、ECS 或功能概览，避免直接从孤立组件页建立整体结论。
- 将[更新说明](docs/spatial-sdk_更新说明.md)视为变更记录，不作为概念入口。
- 涉及承载与生命周期时，先区分 Planar/Volumetric WindowContainer、Stage，以及 Shared Space/Full Space，再推荐具体 API。
- 2D UI 问题结合 Spatial UI 与设计规范；3D 运行时状态和行为优先使用 ECS、资源、渲染、交互、动画与物理文档。
- PICO Spatial Editor、Shader Graph、Timelines、Plugin 和 Emulator 页面属于界面或工具工作流；若无运行时文档佐证，不要据此推断 Kotlin SDK 行为。
- SpatialML 问题先从独立 spatial-ml 概览和运行时模型开始，明确管线阶段与张量契约后再查算子叶子页。
- 升级或兼容问题同时使用[升级 SDK](docs/spatial-sdk_升级-sdk.md)、[迁移 Android 应用](docs/spatial-sdk_迁移-android-应用.md)和[更新说明](docs/spatial-sdk_更新说明.md)。
- 性能结论先经过性能与调试概览路由；模拟器现象还需结合模拟器与真机差异文档或真机验证。

## 学习路线图

### 通用路径

1. **基础与承载模型**：先读[了解 PICO Spatial SDK 和空间应用](docs/spatial-sdk_了解-pico-spatial-sdk-和空间应用.md)和[了解空间容器 & 空间状态](docs/spatial-sdk_空间容器_了解空间容器-&-空间状态.md)。后续 API 都依赖应用、容器、空间状态及 2D/3D 呈现心智模型。
2. **首个可运行项目**：继续阅读[第二步：创建并运行 Spatial 项目](docs/spatial-sdk_快速开始_第二步：创建并运行-spatial-项目.md)和[项目结构与依赖配置](docs/spatial-sdk_项目结构与依赖配置.md)，先掌握构建、启动和模块关系。
3. **UI 与场景架构**：2D Compose 风格界面进入[Spatial UI 概览](docs/spatial-ui_spatial-ui-概览.md)；3D 场景状态进入[了解 ECS 架构](docs/spatial-sdk_实体-组件-系统（ecs）_了解-ecs-架构.md)和[资源概览](docs/spatial-sdk_资源管理_资源概览.md)。
4. **交互与功能系统**：先读[3D 物体的基础交互](docs/spatial-sdk_交互_3d-物体的基础交互.md)；再按需求进入追踪、渲染、动画、物理、音频、视频、环境感知或 SpatialML。
5. **工具与交付**：Plugin、Editor、Emulator 用于创作和预览；最后用[概览](docs/spatial-sdk_性能与调试_概览.md)、迁移、兼容和更新说明完成验证。

### 按开发背景分支

- **传统 Android 开发者**：平台心智模型 → 空间容器 → 项目结构 → [迁移 Android 应用](docs/spatial-sdk_迁移-android-应用.md) → Spatial UI；仅在需要 3D 时继续 Volumetric、Stage 与 ECS。
- **游戏 / 3D 开发者**：平台与容器模型 → ECS → 资源/AssetBundle → 渲染与材质 → 交互 → 动画/物理/音视频 → Spatial Editor 资产管线 → 性能。
- **空间计算 / visionOS 开发者**：把空间应用映射到 WindowContainer/Stage 与 Shared/Full Space → 对比 2D 面板和 3D 实体 → 学习交互与追踪 → 加入锚点、网格、平面检测、音视频和环境感知。

- [Option](docs/spatial-design_基础_组件_selection-&-input_option.md): Option 将预设的可选项以结构化形式呈现，帮助用户快速做出决策。每个 Option 是独立的选择单元，代表一个具体的可选项，与其他 Option 可能存在互斥（单选）或并列（多选）关系。 [tags: design, component, best-practices]

- [Side Navigation](docs/spatial-design_基础_组件_navigation-&-search_side-navigation.md): Side Navigation 放置在窗口的前沿位置；对于从左到右的语言来说是左侧，而对于从右到左的语言来说是右侧。它提供了应用信息层级的平面视图，使用户可快捷访问同级内容。 [tags: design, component, best-practices]
- [Segmented Controls](docs/spatial-design_基础_组件_navigation-&-search_segmented-controls.md): Segmented Controls 常用于选择选项和切换视图。避免使用 Segmented Controls 来提供操作，如添加、移除或编辑内容。 [tags: design, component, best-practices]

- [Badge](docs/spatial-design_基础_组件_surface-content_badge.md): Badge 用于指示通知、计数或信息说明，吸引用户注意、引导操作。Badge 自身不可交互，所以通常位于其他组件内部，如 Tab Bar、Side Navigation 等。 [tags: design, component, best-practices]
- [List](docs/spatial-design_基础_组件_surface-content_list.md): 列表是提供信息展示、整理信息层级的可交互组件。列表能够高效的展示信息和进行数据分类，从而给用户提供有效指引。 [tags: design, component, best-practices]
- [Tooltip](docs/spatial-design_基础_组件_surface-content_tooltip.md): Tooltip 是信息性的文本标签，帮助用户理解界面元素的功能。Tooltip 自身不可交互。一般作为父元素的解释说明，如 Icon Button 的功能介绍。 [tags: design, component, best-practices]
- [Coach Mark](docs/spatial-design_基础_组件_surface-content_coach-mark.md): Coach Mark 常用于帮助用户理解新的功能或引导用户操作，通常不会阻断用户交互，页面内未被遮挡的 UI 元素可以正常响应。同一时间建议只显示一个 Coach Mark，保证用户能集中注意力。 [tags: design, component, best-practices]
